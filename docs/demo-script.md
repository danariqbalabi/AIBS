# Skenario demo AIBS (3–5 menit)

Gunakan data sintetis. Satu operator mendemokan, satu anggota menjelaskan masalah dan batas produk. Jangan memperlihatkan secret atau OTP di rekaman.

| Waktu | Aksi | Bukti |
| --- | --- | --- |
| 0:00–0:30 | Masalah budget, bahan/saus tidak diketahui dan keluhan beberapa jam kemudian | Pendamping keputusan/catatan, bukan diagnosis |
| 0:30–1:10 | Nadia → menu/alasan → Raka dalam sesi browser terpisah | Katalog sama, hasil berbeda mengikuti profil; aturan backend |
| 1:10–1:55 | Aktifkan AI → foto milik tim → review saus/bahan/porsi | AI hanya kandidat; pengguna mengonfirmasi unknown |
| 1:55–2:35 | “Siang makan ayam kecap, sore kembung, tapi nggak mual” → review | Waktu terpisah, negasi dipertahankan, koreksi tersedia |
| 2:35–3:15 | Konfirmasi konsumsi/waktu → simpan → Jurnal/Hari Ini → refresh | Data persisten; draft/rencana bukan konsumsi |
| 3:15–3:45 | Matikan AI → manual → ringkasan/konsultasi | Fallback selesai tanpa model, batas data jelas |
| 3:45–4:15 | Arsitektur, empat kasus NLP sintetis, evaluasi lanjutan | Dua tugas AI inti; rules/ownership/simpan deterministik |

## Persiapan

- Bekukan commit dan hash APK; uji semua tombol yang direkam.
- Dua sesi browser terpisah untuk Nadia/Raka; jangan mengganti sesi berisi data penting.
- Siapkan foto sendiri dan koneksi internet. Foto nyata perlu diuji sebelum rekaman.
- Jika AI gagal, tunjukkan fallback secara jujur. Jangan menyebut rekaman/mock sebagai panggilan live.
- Klik ganda/retry dapat dibuktikan lewat tes. Hindari analisis berulang yang menghabiskan kuota.
- Pertahankan “Belum tentu penyebab”, label sintetis dan batas instrumen demo. Tidak ada klaim persentase risiko atau efektivitas klinis.

Ketua melengkapi video dan APK publik pada submission. Source, APK dan video harus mengacu build sama. Sertakan langkah instalasi Android dan pastikan kuota/layanan tersedia saat penilaian.
